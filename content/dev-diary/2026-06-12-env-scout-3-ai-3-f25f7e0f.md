### この回の要点（先に読む）

- **変わったこと**: 中島聡さんの3月号メルマガ（5冊分）を分析し、「AIへの権限の与え方」「自然言語でコンピュータを操る3段階の進化モデル」「Claude記憶の定期メンテナンス手順」の3つを開発環境に取り込んだ
- **いままでとの違い**: これまでは「どうAIを動かすか」に集中していたが、今回は「AIに何をさせてよいか」と「AIとの関係をどう段階的に育てるか」という設計レベルの話を明文化した
- **メリット**: AIを安全に使うための「意図的な権限設計」が言語化され、さらに現在の Vault 運用が「AIプログラミングの最先端」であることを確認・明示できた

### 今回取り込んだ3つの原則

**① AIへの権限設計原則（Short Leash / Karpathy式）**

3月10日号より。Andrej Karpathy（元Tesla AI責任者・OpenAI創業メンバー）が提唱する「Short Leash（短いリード）」の考え方です。

犬を散歩させるとき、いきなりリードを外して自由にさせるのではなく、最初は短いリードで動きを制御しながら信頼を積み重ねていく——AIエージェントへの権限管理も同じです。「新しいプロジェクトではまずAIに最小限の権限だけ与え、動作を確認してから広げていく」「外部への送信・削除操作は常に人間の明示的な承認を必要とする」という原則を `methods/development/README.md` に追加しました。

技術的には既に `capability-ticket-guard.py`（許可・禁止リストで実際の操作をブロックする仕組み）として実装済みでしたが、**なぜそうするのかの哲学**が設計手法として文書化されていませんでした。今回、新プロジェクト設計時に毎回意識すべき原則として明記しました。

**② 自然言語でコンピュータを操る3段階モデル（Karpathy式）**

3月24日号より。Karpathy の「Autoresearch」解説から。AIとの付き合い方は3段階で進化するという見立てです。

- Stage 1（命令型）: ChatGPT に1つずつ指示を出す。会話で完結する使い方
- Stage 2（自律型）: Claude Code のようなエージェントが複数ステップを自律実行する
- Stage 3（宣言型）: CLAUDE.md・スキルファイル・Memory Folder など「高レベルなプログラム」でAIの動作と記憶を設計する

**重要な発見**: このVaultは既に Stage 3 の実践です。「CLAUDE.md を書く＝AIをプログラムする」「スキルを作る＝AIに新しい能力を与える」という意識を持つことで、毎回手でプロンプトを書く（Stage 2 の習慣）から抜け出せます。`methods/development/README.md §12` に「AIとの協働段階マップ」として追加しました。

**③ Claudeメモリの明示的コントロール（中島式）**

3月31日号より。Claudeのメモリ機能を「AIに任せっきりにしない」という原則です。

記憶は放っておくと「古くなった情報が残り続ける」（腐敗メモリ）という問題が起きます。月に1回、以下の4ステップで記憶を整理する手順を Memory Folder の運用ルールとして追加しました。

- 確認: 「今あなたは私について何を覚えているか」と確認する
- 編集: 古い・誤った記憶を修正する
- 削除: 完了したプロジェクトの記憶を削除する
- 圧縮: 200行を超えたら詳細をトピックファイルへ移す
