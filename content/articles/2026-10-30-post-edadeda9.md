[What Does a Harness Buy? Tokens, Mostly.（arXiv）](https://arxiv.org/abs/2610.04433)
公開日: 2026-10-03

[Fancy harnesses make coding agents more expensive but not better, study finds（The Decoder）](https://the-decoder.com/fancy-harnesses-make-coding-agents-more-expensive-but-not-better-study-finds/)
公開日: 2026-10-24

これは、前の記事「モデルの点数は、モデルだけの点数ではない」の続きです。

Claude Code のようなアプリでは、画面に出るのは自分の依頼と、返ってきた結果です。アプリがモデルに渡す指示は、画面に出ません。コードを直させるときは、ファイルを開く、中を検索する、コマンドを実行する、といった操作の説明も一緒に渡します。これも画面に出ません。使う側、とくにエンジニアではない人は、そこを意識しません。この記事では、その見えない指示と操作の説明を前文と呼びます。

この論文を取り上げたのは、前文が、1問にかかるコストに関係していると測っていたからです。ここで言う正答率は、課題が解けた割合です。課題は不具合を直すことなので、直せた割合と同じです。同じモデルを3つのアプリに入れると、正答率はほとんど変わりません。変わるのはコストで、最大3倍です。前文の長さと、モデルとの往復の回数で決まります。

前の記事は、モデルの優秀さを評価する点数を、モデルだけの点数として読んではいけない、という話でした。この記事は、その見方で読んだ測定です。モデルは固定したまま、コードを書かせるアプリだけを3つ替えています。

### 何を揃えて比べたか

論文は、山東大学の Yangze Liu さんと Zhongyi Han さんによるものです。2026年10月3日に arXiv で公開され、The Decoder が10月24日に伝えています。リンクは末尾にまとめてあります。

この記事で使う言葉は、次のとおりです。

- 正答率：この記事での意味 課題が解けた割合。この試験では、不具合を直してテストが通った問題の割合。直せた割合と同じ
- コスト：この記事での意味 モデルに送った文章の量（トークン）に、価格表の単価を掛けた額。この論文では、実際の支払額ではなく、この計算で出した額
- トークン：この記事での意味 モデルが文章を数えるときの単位。日本語なら1文字が1〜2トークン程度
- 前文：この記事での意味 アプリが毎回先頭に付けて送り直す、画面に出ない指示と、ファイルを開く・検索する・コマンドを実行するといった操作の説明
- 手順の数：この記事での意味 1問を直し終えるまでに、アプリがモデルと往復した回数

比べたアプリは3つです。前文の長さと、モデルに許した操作が違います。

- Claude Code：前文の長さ 16,581 トークン／モデルに許した操作 ファイル操作、検索、コマンド実行など。長いやりとりは自動で要約
- OpenCode：前文の長さ 7,025 トークン／モデルに許した操作 Claude Code と同じくファイル操作や検索を持つ
- mini-SWE-agent：前文の長さ 829 トークン／モデルに許した操作 コマンド実行ひとつだけ。要約の機能も無い

モデルは、中身を公開している5つです。Qwen が2つ、DeepSeek、GLM、HY が1つずつです。Qwen の2つは、研究者が自分たちのサーバーで動かしました。DeepSeek、GLM、HY は、各社の窓口（API: Application Programming Interface）で呼びました。窓口で呼んだ3つは、送ったトークンごとに課金されます。自前のサーバーで動かした2つと、窓口で呼んだ3つのどちらも、送ったトークン数に価格表の単価を掛けてコストを計算できます。この論文のコストは、実際に払った額ではなく、その計算で出した額です。

Claude Opus 5 だけは、扱いが違います。Claude Code の月額契約で走らせたので、トークンごとの単価がありません。そのため Opus 5 は、上限の目安として Claude Code の中だけで走らせました。アプリの比較にも、コストの比較にも入れていません。論文は、その理由をこれ以上書いていません。

課題は、公開されている不具合を直させる試験 SWE-bench Verified です。前の記事でも取り上げました。直したあとにテストが通れば正解です。難しい方の45問は5つのモデル全部で、残る447問は2つの Qwen で測りました。

### 正答率は、アプリを替えてもほとんど動かなかった

難しい45問の結果です。表に入っているのは、3つのアプリすべてで比べた5つのモデルだけです。

- HY4-Preview：Claude Code 23/45（51%）／mini-SWE-agent 26/45（58%）／OpenCode 21/45（47%）
- GLM-5.3-Flash：Claude Code 22/45（49%）／mini-SWE-agent 20/45（44%）／OpenCode 18/45（40%）
- DeepSeek-V4-Flash：Claude Code 21/45（47%）／mini-SWE-agent 22/45（49%）／OpenCode 19/45（42%）
- Qwen3.8-27B：Claude Code 19/43（44%）／mini-SWE-agent 17/45（38%）／OpenCode 17/45（38%）
- Qwen3.6-35B-A3B：Claude Code 11/45（24%）／mini-SWE-agent 15/45（33%）／OpenCode 11/45（24%）

Qwen3.8 の Claude Code だけ、分母が43です。45問のうち2問は、測定の仕組みの不具合で採点できず、不正解には数えていません。

Claude Opus 5 の 36/45（80%）は、この表に入れていません。上に書いたとおり、Claude Code の中だけで走らせ、他のアプリとは比べていません。

横に見ると、同じモデルでアプリを替えても、直せた問題の数は2問から5問しか変わりません。アプリもモデルも問題もそのままで、同じ45問をもう一度解かせても、正解の数は最大で3問動きます。一度目は正解だった問題が二度目は不正解になる、またはその逆です。アプリを替えたときの変化は、この入れ替わりと同じ程度です。入れ替わる問題の割合は、もう一度解かせた場合でもアプリを替えた場合でも、真ん中の値で13%でした。モデルを替えると22%でした。縦に見ると、表の5つでは、Claude Code の列で Qwen3.6 の24%から HY4 の51%まで開きます。表に入っていない Opus 5 は80%で、いちばん低い24%の3倍以上です。

447問では、前文がいちばん長い Claude Code と、いちばん短い mini-SWE-agent を比べました。正答率の差は5パーセント以内でした。論文は、この差では同じだとしています。

### コストは、アプリによって最大3倍違った

同じモデル、同じ問題、同じ単価で、1問のコストはアプリによって最大3倍違いました。金額の単位は中国元です。

- GLM-5.3-Flash：何が違ったか 1回あたりのコスト／数字 Claude Code 1.81 元、mini-SWE-agent 0.97 元、OpenCode 0.56 元
- DeepSeek-V4-Flash：何が違ったか 手順の数／数字 mini-SWE-agent 141 回、Claude Code 104 回

コストは「前文の長さ × 手順の数」で決まります。GLM では、前文が長い Claude Code が高くつきました。DeepSeek では、前文が短い mini-SWE-agent が往復を141回まで増やしました。その結果、前文が長い Claude Code とほぼ同じ額になりました。ファイルの中身やコマンドの結果として戻ってくる文章の量は、3つのアプリでほぼ同じです。違いは前文と往復の回数にあります。前文が短いアプリが、必ず安いわけではありません。

### 正答率が下がったのは、アプリの賢さではなく設定だった

アプリを替えても、正答率は上がりませんでした。下がったのは、アプリが賢くないからではなく、設定の違いでした。OpenCode は447問で、最大およそ9パーセント遅れました。あるモデルでは、その差の半分が、返事の長さの上限で実行が途中終了した分でした。Qwen3.8 の447問で、この上限で失敗した回数は OpenCode が33回でした。途中で止まっても続けさせる Claude Code は1回です。また、答える前に考えの過程を書かせる機能を切ると、Qwen3.6 では mini-SWE-agent だけが11パーセント下がりました。HY4 では、Claude Code の中で同じ機能を切ると11パーセント下がりました。

測り方で1つ、大事な点があります。初めの実験では、ネットにつないだままでした。すると DeepSeek と Qwen は、439回のうち312回で正解の修正を拾ってきていました。拾い先は、公開のプログラム置き場 GitHub です。この結果は捨て、以降はネットを切って測り直しています。

この測定に入っているのは、モデルとアプリだけです。ユーザーが自分で書く指示ファイルや、出てきた答えを別の仕組みで確かめる段は入っていません。言えるのは、アプリを替えても正答率は、何も替えずにもう一度解かせたときに入れ替わる範囲を超えなかった、までです。

以前の比較では、アプリを替えただけで正答率が大きく開いた、という報告があります。複数のモデルをまとめて比べて23.8パーセント開いたもの（[Yao ほか、2026](https://arxiv.org/abs/2605.27922)）、1つのモデルに固定して27.4パーセント開いたもの（[Zheng ほか、2026](https://arxiv.org/abs/2606.12344)）です。[Zhipu AI](https://zhuanlan.zhihu.com/p/2070504528416337941) は、自社のアプリが Claude Code を2.4パーセント上回る、と宣伝しています。

この論文の試験では、その差が本当にアプリの差かは、問の数によって限界があります。45問では、13パーセント開いていても、半分の確率でしか見つけられません。447問でも、およそ5パーセントより小さい差は区別できません。宣伝の2.4パーセントは、どちらの問の数でも区別できない大きさです。論文は、以前の大きな差はアプリの出来ではなく、返事を途中で切る設定や、ネットにつないだまま測っていたことの違いだった可能性が高い、としています。

この結論が弱くなる条件もあります。Opus 5 は月額契約で Claude Code の中だけで動かし、他のアプリとは比べていません。Claude のモデルで同じことが言えるかは、この論文では分かりません。試した組み合わせも小さく、論文自身が、原因を一つに特定はできないとしています。別の試験でも、3つのアプリの成功数は19、20、20で、順番は付きませんでした。試験名は Terminal-Bench 2.1 で、採点できたのは50問です。447問を5つのモデル全部で解かせて、正答率の差が、何も替えずにもう一度解かせたときの入れ替わりをはっきり超えたなら、この結論は外れます。

### この論文が示すこと

アプリは、画面に出ない指示を毎回モデルに渡しています。コードを直させるアプリでは、ファイルを開く、検索する、コマンドを実行する、といった操作の説明も一緒です。使う側は、そこを意識しません。この論文は、同じモデルのままアプリだけを3つ替え、その見えない部分が結果にどう出るかを測りました。

正答率は、アプリを替えてもほとんど変わりません。何も替えずにもう一度解かせただけで、正解が入れ替わる問の数と、同じ程度です。モデルを替えれば、正答率は大きく変わります。

変わるのは、1問にかかるコストです。最大で3倍違います。画面に出ない指示が長いか、モデルとの往復が多いか、で決まります。指示が短いアプリが、必ず安いわけではありません。

正答率が下がって見えたときは、返事が途中で切れる設定や、ネットから正解を拾っていたことが原因でした。アプリの宣伝で出る数パーセントの差は、この試験では区別できない大きさです。
