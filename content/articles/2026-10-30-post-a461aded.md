> [What Does a Harness Buy? Tokens, Mostly.（arXiv）](https://arxiv.org/abs/2610.04433)
> 公開日: 2026-10-03

新しいモデルが出るたびに、順位や点差や「このモデルが一番」という報道が出ます。ここで言うモデルの点数は、そのモデルの優秀さを評価した点数です。見出しにはモデル名しか出ないことが多く、その点数は、モデル単体の優秀さに見えます。何を測ったかは、見出しには書かれていません。

点数を見るときは、生成AIが4つの層で動いていることを先に置く必要があります。報道の点数は、そのうちの一部を測った記録です。

### 生成AIは4つの層で動いている

生成AIの仕事は、モデルだけでは動きません。名前が似ているので同じものに見えますが、仕事は4つの層でできています。内側から順に並べます。

- 1：名前 モデル／何をするか 渡された文章のつづきを返す土台／誰が作るか モデルの開発元／Claude での例 Claude（Opus、Sonnet）／他社の例 GPT-5、DeepSeek
- 2：名前 アプリ／何をするか 土台に作業をさせる外側。画面に出ない指示と道具を毎回足す／誰が作るか アプリの開発元／Claude での例 Claude.ai のチャット、Claude Code／他社の例 ChatGPT、OpenCode
- 3：名前 ユーザーの指示ファイル／何をするか アプリに「この場所ではこう動け」と足す／誰が作るか ユーザー／Claude での例 CLAUDE.md／他社の例 アプリごとに別の名前
- 4：名前 外側の検証／何をするか 出てきた答えを、別の仕組みで確かめて通す・止める／誰が作るか ユーザー／Claude での例 テスト、評価基準、関所／他社の例 同じ

層1のモデルは、それ単体では画面も持たず、ファイルも開きません。DeepSeek のように、中身の重みを公開している系統もあります。

層2のアプリは、同じモデルでも、渡し方と返ってきたものの扱い方が違います。質問に答えさせるアプリが Claude.ai のチャットです。コードを読ませて直させるアプリが Claude Code です。別の会社で同じ対比をすると、モデルが GPT 系で、質問に答えさせるアプリが ChatGPT です。アプリは、ユーザーの依頼文の前に、画面に出ない指示と道具の説明を毎回足してモデルに渡します。

向きを間違えやすいので、一度だけ確かめます。Claude が Claude Code を使うのではありません。Claude Code が、Claude に文章を渡して使います。

層3は、その場所の決まりごとをアプリに足すファイルです。層4は、出てきた答えを別の仕組みで確かめて、通すか止めるかです。この外側の2層は、最近「ハーネスエンジニアリング」と呼ばれて勧められている部分です。ハーネスは、モデルに被せる外側の仕組み（指示文、道具、これまでのやりとりの管理）のことです。ユーザーが自分で書けるのは、この外側の2層だけです。

### 報道の点数は、このうちどこを測っているか

普通は、新しいモデルの記事に出る点数を、そのモデルの優秀さとして読みます。その読み方は、点数がモデル単体で測れる、という前提に立っています。前提が成り立つかは、課題の種類で分かれます。

- 問答型：何をさせるか 質問に答えさせ、知識や推論をチャットの往復で見る／近い使い方 Claude.ai のチャット、ChatGPT／アプリの混ざり方 小さい
- 作業型：何をさせるか 終わりのある仕事をさせ、結果で採点する／近い使い方 Claude Code／アプリの混ざり方 必ず混ざる

作業型の代表が、公開の不具合修正試験 SWE-bench Verified です。プログラムの置き場であるリポジトリの中にある不具合を、アプリに直させます。採点は、直したあとにテストが通るかで決まります。作業型では、アプリが無ければモデルは課題に手を付けられません。点数には層2のアプリが必ず混ざります。層3と層4は、この種の点数には普通入っていません。

一般の記事の見出しは、層1のモデル名だけです。実際の1回の測定は、少なくとも3つが揃って初めて意味を持ちます。どのモデルか。どのアプリか。問答型か作業型か、どの課題集か。

同じ Claude を、チャットで問答させる場合と、Claude Code で不具合を直させる場合を考えます。土台は同じです。それでも、前者はユーザーの質問がほぼそのまま届き、後者は画面に出ない指示と道具の説明が毎回先頭に付きます。課題も、答える仕事と、直して試す仕事で別です。この2つの点数を並べて、同じ Claude の実力だと言う人はいません。別のモデルの点数を見出しだけで並べるのは、これと同じことをしています。

### 次の記事で読むこと

この分け方のあとに読む測定が、山東大学の Yangze Liu さんと Zhongyi Han さんの論文です。モデルを固定し、コードを書かせるアプリだけを替えています。何点だったか、コストがどれだけ開いたか、順位表の点差がその測定でどう読めるかは、次の記事にまとめます。この記事では繰り返しません。

4つの層が良くするものは、それぞれ別です。論文が測るのは層1と層2だけで、層3と層4は入っていません。

- 1 モデル：良くなるもの 一発で正しい答えを出す割合／論文の試験の点数に出るか 出る
- 2 アプリ：良くなるもの 使い勝手、道具の種類、許可の仕組み、コスト／論文の試験の点数に出るか 出ない（コストに出る）
- 3 ユーザーの指示ファイル：良くなるもの その場所の決まりごとを守る精度／論文の試験の点数に出るか 測っていない
- 4 外側の検証：良くなるもの 間違った答えを通さないこと／論文の試験の点数に出るか 測っていない

### 見出しの点数で確かめること

モデル名の横に、どのアプリで測ったか、問答型か作業型かが書いてあるかを確かめます。書いていない点数は、別の記事の点数と並べられません。上の表で「出ない」「測っていない」とした層は、この試験の点数には入っていません。入っていないからといって、その層を整えることが無駄だとは言えません。

次の記事は「直せる割合はモデルが決め、コストはアプリが決める」です。同じモデルのままアプリを3つ替えたとき、直せる割合とコストのどちらが動いたかを、そこで読みます。
