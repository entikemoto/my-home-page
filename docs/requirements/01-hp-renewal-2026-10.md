# 要件: ホームページ刷新 2026-10（X 中心の書庫化と UI 改善）

> 雛形の正本: `~/.claude/skills/new-project/scripts/templates/requirements.template.md`
> 作成日: 2026-10-24。作成: オーナーと Claude Code の対話（本リポジトリでのプランニング・セッション）で確定した内容の書き戻し。

## 0. 背景（なぜ作るか）

- 2026 年 7 月以降、開発環境の見直しで記事配信が止まり、HP の最新記事は 2026-06-25 のまま 4 か月更新されていない
- 運用は「note の朝便・夜便」中心から「X の Article 機能（手動投稿）」中心に変わった。しかし HP の記事データ契約は note 前提（`noteArticleUrl` 必須）で、X 中心の記事は HP に載せられない
- 配信装置（vault-publisher）の HP 係は「発信一覧に 1 行追記」だけで、記事の全文は HP に届かない。全文を書き出す旧経路は 2026-05 の整理で切り離されていた
- note の全記事を毎回取り直す取り込みスクリプトが、記事が増えるほど重く壊れやすい
- 認知の土台（sitemap・OGP 画像・RSS）が無く、X で共有しても記事カードが出ない

## 1. 最初の一周（これだけ作る）

**流れ**: オーナーが X に Article を手動投稿 → 橋渡しスクリプトで配信トレイへ → 配信装置が note に投稿 → **HP に記事ファイルを 1 本追加して push** → Vercel が自動ビルド → 記事ページが公開される。

作るもの:

1. **新しい記事形式**（Markdown 1 ファイル＝1 記事、frontmatter に X と note の URL・タグ・カバー画像）を HP が読めるようにする。過去 219 ファイル（JSON）はそのまま残し、同じ画面で混在表示する
2. **配信装置の HP 係**を「1 行追記」から「記事ファイル 1 本追加＋発信一覧 1 行追記」に変える（vault-publisher 側の変更）
3. **記事ページの見せ方を統一**: 見出しの下に「X で読む」「note で読む」「元記事」の導線、本文は全文。過去記事にも同じ扱い（X の投稿 ID は記事生成側の配信記録から対応表を作って付ける）
4. **認知の土台**: sitemap・robots・RSS・記事ごとの OGP 画像
5. **UI 改善**: トップの短縮（最新記事を先頭に）、ナビ整理、記事一覧と記事本文の読みやすさ、X 中心に合わせた文言

### 成功の基準

- 配信装置のテスト（モック）が緑で、実記事 1 本を配信すると HP に記事ページとして現れる（Vercel の deployment status が success）
- 過去記事のうち X 投稿記録のあるものに「X で読む」が出る
- X で記事 URL を共有したとき、タイトル入りのカード画像が出る
- オーナーが Vercel のプレビュー URL で新旧を見比べて承認する（UI）
